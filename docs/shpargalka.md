# Шпаргалка по командной строке Linux и bash

Набор «кирпичиков»: каждая команда с пояснением и маленьким примером.
Из них собираются решения. Примеры запускай в настоящем Linux (контейнер Ubuntu),
на macOS часть флагов отличается.

---

## 1. Основы: конвейеры и перенаправления

| Запись | Что делает |
|--------|-----------|
| `cmd1 \| cmd2` | Вывод первой команды становится вводом второй (конвейер, pipe) |
| `cmd > file` | Записать вывод в файл (перезаписать) |
| `cmd >> file` | Дописать вывод в конец файла |
| `cmd < file` | Подать файл на вход команде |
| `cmd 2> file` | Перенаправить поток ошибок (stderr) |
| `cmd >&2` | Отправить вывод в stderr (так печатают сообщения об ошибках) |
| `cmd > /dev/null` | Выбросить вывод |
| `cmd1 && cmd2` | Выполнить вторую, только если первая завершилась успешно |
| `cmd1 \|\| cmd2` | Выполнить вторую, только если первая завершилась с ошибкой |

```bash
ls | wc -l                 # посчитать количество файлов в папке
echo "ошибка" >&2          # сообщение в stderr
```

У каждой команды есть **код возврата**: `0` значит успех, любое другое число значит ошибку.
Посмотреть код последней команды: `echo $?`.

## 2. Просмотр и обработка текста

### cat, head, tail
```bash
cat file            # вывести файл целиком
head -n 5 file      # первые 5 строк
tail -n 5 file      # последние 5 строк
head -n 1 file      # только первая строка
```

### grep: поиск строк по шаблону
```bash
grep "root" file          # строки, где есть "root"
grep -v "^#" file         # -v: инвертировать, то есть строки БЕЗ совпадения (здесь убираем комментарии)
grep -E "a|b" file        # -E: расширенные регулярные выражения
grep -o "[0-9]+" file     # -o: вывести только совпавшую часть, а не всю строку
grep -c "x" file          # посчитать количество совпавших строк
grep -i "x" file          # без учёта регистра
grep -r "x" dir/          # рекурсивно по папке
grep -n "x" file          # с номерами строк
grep -q "x" file          # тихий режим: ничего не печатает, только код возврата (0 найдено, 1 нет)
```
Полезные элементы регулярок:
- `^` начало строки, `$` конец строки
- `.` любой символ, `*` ноль или больше повторов, `+` один или больше (в `-E`)
- `[a-z]` любой символ из диапазона, `[^a-z]` любой символ, кроме диапазона
- `[A-Za-z_]` латинские буквы и подчёркивание
- `\b` граница слова (в GNU grep)
- `^[[:space:]]*$` пустая строка или строка из одних пробелов

### cut: вырезать колонки
```bash
cut -d ':' -f 1 file      # -d разделитель, -f номер поля: первое поле, разделитель двоеточие
cut -d ':' -f 1,3 file    # поля 1 и 3
cut -f 2 file             # без -d разделитель по умолчанию табуляция
cut -c 1-5 file           # символы с 1 по 5
```
`cut` не умеет менять порядок полей: `-f 2,1` всё равно выведет сначала первое.
Для перестановки и работы с пробелами лучше `awk`.

### awk: обработка по колонкам
```bash
awk '{print $1}' file            # первая колонка (разделитель: любые пробелы/табы)
awk '{print $2, $1}' file        # поменять колонки местами, вывод через пробел
awk -F ':' '{print $1}' file     # -F задаёт разделитель
awk '$2 > 100' file              # строки, где второе поле больше 100
awk 'NF' file                    # только непустые строки (NF число полей)
awk '{print length($0)}' file    # длина каждой строки
```

### sort: сортировка
```bash
sort file              # по алфавиту
sort -r file           # в обратном порядке
sort -n file           # как числа (иначе "10" окажется раньше "9")
sort -rn file          # числа по убыванию
sort -k 2 file         # по второй колонке
sort -k 2 -n -r file   # по второй колонке, как числа, по убыванию
sort -t ':' -k 3 -n file   # -t задаёт разделитель колонок
sort -u file           # сортировка и удаление повторов
```

### uniq: повторы (работает только с соседними строками, поэтому почти всегда после sort)
```bash
sort file | uniq           # убрать повторы
sort file | uniq -c        # посчитать, сколько раз встретилась каждая строка
sort file | uniq -d        # показать только те строки, что повторяются
sort file | uniq -u        # показать только уникальные строки
sort file | uniq -w 32     # сравнивать только первые 32 символа строки
sort file | uniq -D -w 32  # вывести ВСЕ строки-повторы, сравнивая первые 32 символа
```

### tr: замена и удаление символов
```bash
echo "hello" | tr 'a-z' 'A-Z'       # перевести в верхний регистр
echo "a b  c" | tr -s ' '           # -s: сжать подряд идущие повторы в один
echo "a b c" | tr ' ' '\n'          # заменить пробелы на переводы строки (слова в столбик)
echo "a1b2" | tr -d '0-9'           # -d: удалить символы
echo "a1b2" | tr -c 'a-z' '\n'      # -c: всё, что НЕ из набора, заменить на перевод строки
```
`tr` работает с символами, а не со строками, и читает только стандартный ввод
(файл подают через `<` или `cat file |`).

### sed: потоковый редактор
```bash
sed 's/old/new/' file          # заменить первое вхождение в каждой строке
sed 's/old/new/g' file         # заменить все вхождения (g = global)
sed 's/    /\t/g' file         # заменить 4 пробела на табуляцию (в GNU sed \t понимается)
sed -E 's/ {4}/\t/g' file      # то же через регулярку: "пробел ровно 4 раза"
sed -n '1p' file               # вывести только первую строку
sed '/^#/d' file               # удалить строки, начинающиеся с #
sed -i 's/a/b/' file           # -i правка прямо в файле (осторожно!)
```
Замена без правки исходного файла: `sed 's/a/b/' in.txt > out.txt`.

### wc: подсчёт
```bash
wc -l file     # строки
wc -w file     # слова
wc -c file     # байты
```

## 3. Файлы и каталоги

```bash
pwd                    # где я сейчас
ls -l                  # подробный список, с правами
ls -la                 # включая скрытые файлы (начинаются с точки)
cd /path               # перейти в папку
mkdir -p a/b/c         # создать папку (вместе с родителями)
cp src dst             # копировать файл
cp -r dir1 dir2        # копировать папку
mv old new             # переместить или переименовать
rm file                # удалить (без корзины!)
rm -r dir              # удалить папку
touch file             # создать пустой файл или обновить время изменения
file name              # определить тип файла
```

### Права доступа
`ls -l` показывает, например, `-rwxr-xr-x`:
первый символ тип (`-` файл, `d` папка), дальше три тройки прав: **владелец, группа, остальные**.
`r` чтение (4), `w` запись (2), `x` запуск (1).

```bash
chmod +x script        # сделать исполняемым для всех
chmod 755 script       # rwxr-xr-x: владелец всё, остальные читают и запускают
chmod 644 file         # rw-r--r--
chmod u+x,go-w file    # u владелец, g группа, o остальные; + добавить, - убрать
```

### Установка команды в систему
Программы, которые можно запускать по имени из любого места, лежат в папках из `$PATH`.
Для своих программ принята папка `/usr/local/bin`.
```bash
echo "$PATH"                              # список папок, где ищутся команды
sudo cp script /usr/local/bin/            # копирование требует прав администратора
sudo chmod 755 /usr/local/bin/script
sudo install -m 755 script /usr/local/bin/   # install = копирование + выставление прав одной командой
```
`sudo` выполняет команду от имени администратора. Писать в `/usr/local/bin` без него нельзя.
Проверить, что команда видна: `command -v script` или `which script`.

### Запуск своего скрипта
Первая строка скрипта задаёт интерпретатор (shebang):
```bash
#!/usr/bin/env bash
```
Запуск: `./script` (нужен бит `x`) или `bash script` (не нужен).

## 4. Поиск файлов: find

```bash
find . -name "*.c"                 # файлы по маске, рекурсивно от текущей папки
find /path -type f                 # только обычные файлы (d для папок)
find . -maxdepth 1 -type f         # не заходить в подпапки (искать только на верхнем уровне)
find . -name "*.c" -o -name "*.py" # -o: ИЛИ (несколько расширений)
find . \( -name "*.c" -o -name "*.py" \) -type f   # скобки группируют условия, их надо экранировать
find . -empty -type f              # пустые файлы (размер 0)
find . -size 0                     # то же, через размер
find . -type f -exec wc -l {} \;   # выполнить команду для каждого найденного файла ({} подставляет имя)
find . -type f -print0 | xargs -0 md5sum    # безопасная передача имён через нулевой байт
```
Почему `-print0` и `-0`: имена файлов могут содержать пробелы. Нулевой символ
разделяет имена надёжно, обычный перевод строки нет.

`xargs` превращает строки со входа в аргументы команды:
```bash
echo "a b c" | xargs echo x        # выполнит: echo x a b c
find . -name "*.txt" | xargs wc -l
```

## 5. Контрольные суммы (сравнение содержимого файлов)

```bash
md5sum file              # хэш содержимого: одинаковое содержимое даёт одинаковый хэш
sha256sum file           # надёжнее
md5sum file1 file2       # вывод: <хэш>  <имя файла>
```
Вывод `md5sum` это строка «хэш, два пробела, имя файла». Хэш занимает ровно 32 символа
(у sha256 их 64). Поэтому по хэшам можно искать совпадения. Например, отсортировать
и найти повторяющиеся первые 32 символа (см. `uniq -w`).
На macOS вместо `md5sum` есть `md5 -r`.

## 6. Архивы: tar

```bash
tar -cf archive.tar file1 file2      # c: создать, f: имя архива
tar -cf archive.tar dir/             # заархивировать папку
tar -czf archive.tar.gz dir/         # z: ещё и сжать gzip
tar -tf archive.tar                  # t: показать содержимое архива
tar -xf archive.tar                  # x: распаковать
tar -xf archive.tar -C /target       # -C: распаковать в другую папку
tar -cf archive.tar -T list.txt      # -T: взять список файлов из файла
find . -name "*.txt" -print0 | tar -cf a.tar --null -T -    # список файлов из конвейера (надёжно для пробелов)
```
Порядок важен: `f` должна идти последней в связке флагов, сразу перед именем архива.

## 7. Основы bash-программирования

### Переменные
```bash
name="world"               # без пробелов вокруг "="
echo "Hello, $name"        # подстановка в двойных кавычках
echo 'Hello, $name'        # в одинарных кавычках подстановки нет
echo "${name}_file"        # фигурные скобки отделяют имя переменной от текста рядом
result=$(ls | wc -l)       # $(...) подстановка команды: результат команды в переменную
n=$((3 + 4 * 2))           # арифметика в $(( ))
```

### Аргументы скрипта
| Переменная | Значение |
|-----------|----------|
| `$0` | имя самого скрипта |
| `$1`, `$2`, ... | первый, второй... аргумент |
| `$#` | количество аргументов |
| `$@` | все аргументы (в кавычках `"$@"` каждый остаётся отдельным словом) |
| `$?` | код возврата предыдущей команды |

### Условия
```bash
if [[ $# -eq 0 ]]; then
  echo "нет аргументов" >&2
  exit 1
elif [[ -f "$1" ]]; then
  echo "это файл"
else
  echo "что-то другое"
fi
```
Проверки внутри `[[ ... ]]`:

| Проверка | Смысл |
|----------|-------|
| `-f path` | существует и это обычный файл |
| `-d path` | существует и это папка |
| `-e path` | существует (любого типа) |
| `-s path` | существует и НЕ пустой |
| `-z "$s"` | строка пустая |
| `-n "$s"` | строка не пустая |
| `"$a" = "$b"` | строки равны |
| `"$a" != "$b"` | строки не равны |
| `$a -eq $b` | числа равны (`-ne`, `-lt`, `-le`, `-gt`, `-ge`) |
| `"$s" == *.c` | строка подходит под маску (без кавычек справа) |
| `"$s" =~ ^#` | строка подходит под регулярку |
| `! условие` | отрицание |

`exit N` завершает скрипт с кодом N. `exit 0` успех, ненулевой значит ошибка.

### Циклы
```bash
for f in *.txt; do         # по файлам, подходящим под маску
  echo "$f"
done

for i in 1 2 3; do echo "$i"; done

for arg in "$@"; do        # по всем аргументам скрипта
  echo "$arg"
done

while read -r line; do     # читать строки со входа по одной
  echo "строка: $line"
done < file                # источник строк: файл

some_command | while read -r line; do    # или из конвейера
  echo "$line"
done
```
`read -r` не даёт обратным слэшам съедаться. Всегда пиши с `-r`.

### Работа со строками (встроенные возможности bash, без внешних команд)
```bash
s="Hello"
echo "${#s}"               # длина строки: 5
echo "${s:1:3}"            # подстрока: с позиции 1, длиной 3 -> "ell"
echo "${s/l/L}"            # заменить первое вхождение -> "HeLlo"
echo "${s//l/L}"           # заменить ВСЕ вхождения -> "HeLLo"
echo "${s#He}"             # отрезать шаблон с начала -> "llo"
echo "${s%lo}"             # отрезать шаблон с конца -> "Hel"
f="/home/user/a.tar.gz"
echo "${f##*/}"            # всё после последнего "/" -> "a.tar.gz" (имя файла)
echo "${f%.*}"             # убрать последнее расширение -> "/home/user/a.tar"
echo "${f##*.}"            # только расширение -> "gz"
```
Аналоги командами: `basename "$f"` (имя файла), `dirname "$f"` (папка).

### printf: форматированный вывод
```bash
printf "%s\n" "текст"            # строка и перевод строки
printf "%5s|\n" "ab"             # выровнять по ширине 5 справа -> "   ab|"
printf "%*s\n" 10 ""             # ширина берётся из аргумента: 10 пробелов
printf -v var "%*s" 10 ""        # -v: результат записать в переменную, а не печатать
```
Трюк «создать строку из N одинаковых символов»: получить N пробелов через `printf -v`,
а затем заменить пробелы на нужный символ через `${var// /символ}`.

`echo` проще, но у `printf` поведение предсказуемее (особенно с `\n`, `-` в начале и т. п.).

### Кавычки: главное правило
Почти всегда пиши переменные в двойных кавычках: `"$var"`, `"$1"`.
Без кавычек bash разобьёт значение по пробелам, и имена файлов с пробелами сломаются.
ShellCheck будет ругаться именно на это.

### Функции
```bash
usage() {
  echo "Use: $0 file" >&2
  exit 1
}
[[ $# -lt 1 ]] && usage
```

### Полезные спецсимволы
| Запись | Значение |
|--------|----------|
| `$'\t'` | символ табуляции (для подстановки в команды, где `\t` не понимается) |
| `*.c` | маска: любое количество любых символов (раскрывается в список файлов) |
| `?` | маска: ровно один символ |
| `~` | домашняя папка |
| `"$(cmd)"` | вывод команды как строка |
| `#` | комментарий до конца строки |

## 8. Массивы и словари в bash

```bash
arr=(a b c)
arr+=(d)                     # добавить элемент
echo "${arr[0]}"             # первый элемент
echo "${arr[@]}"             # все элементы
echo "${#arr[@]}"            # количество элементов

declare -A seen              # ассоциативный массив (словарь), bash 4+
seen["key"]=1
if [[ -n "${seen[key]}" ]]; then echo "уже видели"; fi
```
На macOS стандартный bash старый (3.2) и словари не поддерживает. В Linux всё работает.

## 9. Проверка скриптов

```bash
shellcheck script.sh       # статический анализатор: найдёт типичные ошибки и опасные места
bash -n script.sh          # проверить только синтаксис, не выполняя
bash -x script.sh          # запуск с трассировкой: печатает каждую выполняемую команду
```
Установка: `apt install shellcheck` (Linux), `brew install shellcheck` (macOS).
Сайт с онлайн-проверкой: https://www.shellcheck.net/

Надёжная «шапка» для скриптов:
```bash
#!/usr/bin/env bash
set -euo pipefail
# -e: остановиться при первой ошибке
# -u: ошибка при использовании неопределённой переменной
# -o pipefail: ошибка в любой части конвейера считается ошибкой всего конвейера
```

## 11. Где искать данные для тренировки

- `/etc/passwd`: пользователи системы, поля разделены `:`.
- `/etc/protocols`: сетевые протоколы, поля разделены табами, есть строки-комментарии с `#`.
- Свои тестовые файлы можно создавать так:
  ```bash
  printf '#include <stdio.h>\nint main(void){ return 0; }\n' > hello.c
  ```
- Разница macOS и Linux: на маке `sed -i` требует аргумент (`sed -i '' ...`),
  `md5sum` называется `md5`, у `grep`, `sort`, `find` есть отличия. Проверяй решения в Linux.
